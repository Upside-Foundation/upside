# Join a public network with a full node

Start with [mainnet](../networks/mainnet.md) or [testnet](../networks/testnet.md) and set its node variables. You also need `curl`, `jq`, and a SHA-256 checksum tool.

These steps set up a new full node. Complete validator registration after synchronization if you plan to validate.

## 1. Initialize a new home

Run this only for a new node home. Existing validator state must follow a recovery or migration procedure.

Open a dedicated Bash shell after exporting the network profile. Enable failure handling so a failed check stops the setup:

```bash
bash
```

In that shell:

```bash
set -euo pipefail
: "${UPSIDE_BIN:?Select the node binary}"
: "${NODE_HOME:?Select a new node home}"
: "${CHAIN_ID:?Select the network}"
: "${MONIKER:?Choose a node name}"
if [ -e "$NODE_HOME" ]
then
  printf 'Stop: node home already exists: %s\n' "$NODE_HOME" >&2
  exit 1
fi
"$UPSIDE_BIN" init "$MONIKER" --chain-id "$CHAIN_ID" --home "$NODE_HOME"
```

Initialization creates the node identity and consensus key files. Continue in this shell. If any command fails, inspect the partially created home before retrying. Do not initialize over it.

## 2. Verify and install genesis

The network profile selects a genesis file from the source checkout. Check the file before copying it:

```bash
printf '%s  %s\n' "$GENESIS_SHA256" "$GENESIS_FILE" | sha256sum --check - \
  || { printf 'Stop: %s does not match GENESIS_SHA256\n' "$GENESIS_FILE" >&2; exit 1; }
GENESIS_CHAIN_ID="$(jq -r '.chain_id // empty' "$GENESIS_FILE")" || GENESIS_CHAIN_ID=""
if [ -z "$GENESIS_CHAIN_ID" ] || [ "$GENESIS_CHAIN_ID" != "$CHAIN_ID" ]
then
  printf 'Stop: the genesis chain ID is %s, not %s\n' "${GENESIS_CHAIN_ID:-empty}" "${CHAIN_ID:-empty}" >&2
  exit 1
fi
```

These commands compare the checksum with `GENESIS_SHA256` and the chain ID with `CHAIN_ID`, and stop if either differs. On macOS, replace `sha256sum --check -` with `shasum -a 256 --check -`.

After both checks match:

```bash
cp "$GENESIS_FILE" "$NODE_HOME/config/genesis.json"
```

The original public-network genesis predates the current minting parameters. Validate historical genesis with its matching historical binary. Do not add new parameters to a public network's original genesis to make a current binary accept it. For a new localnet, `genesis validate` checks the fresh genesis generated by that same release.

## 3. Configure peers and service exposure

1. Open `$NODE_HOME/config/config.toml` in a text editor.
2. Set `seeds` or `persistent_peers` to the published values. Use `node-id@host:port` for each entry and commas between entries. Copy the values of `SEEDS` and `PEERS` into TOML as literal strings.
3. Check that the P2P listening address, advertised address, and firewall agree. Keep the CometBFT RPC on loopback (`127.0.0.1`) for a private node.
4. Open `$NODE_HOME/config/app.toml`. Disable unused APIs and bind private APIs to loopback. Check the gRPC listening address explicitly.
5. Set `minimum-gas-prices` to the value of `NODE_MIN_GAS_PRICES`, then save both files.

`minimum-gas-prices` is a local transaction-admission setting. With the dynamic fee market active, native Cosmos transactions also need to meet the base fee and any chain-wide minimum. See [transaction fees](../getting-started/transactions.md) for the fee requirements.

## 4. Install the supported sync state

Select the method compatible with the network and release before starting the node.

| Method | Requirements |
| --- | --- |
| State sync | Snapshot-serving peers, a trusted height and block hash, and a trust period appropriate to the network |
| Restore a snapshot archive | Chain ID, snapshot height, checksum, compatible binary and database backend, and restore instructions |
| Replay history | Original genesis and the exact binary sequence across historical upgrades |

For mainnet, use [state sync](#state-sync-on-mainnet) or the [signed snapshot archive](#restore-the-signed-mainnet-archive). Both need the `v2.0.0` binary from [Install a release binary](../getting-started/install.md#install-a-release-binary), the verified genesis from step 2, and the mainnet peers from step 3. State sync is faster and uses little disk, but the node has no block history before the height it syncs from. The archive also carries about the last 100,000 blocks. Use it if state sync fails or if you need that history. The public testnet has no published snapshots.

A snapshot must not replace your node's P2P or consensus private keys. For an existing validator, preserve its latest signing state and follow the [migration procedure](operations.md#backups-and-migration). Do not initialize or restore over a running validator.

Do not start a fresh current-release node against the historical genesis alone. Historical replay and state sync need the additional inputs listed above. For the binaries that a mainnet replay needs, see [Replay mainnet across the v2.0.0 upgrade](operations.md#replay-mainnet-across-the-v200-upgrade).

### State sync on mainnet

With state sync, the node downloads only the current application state from peers over the P2P network and checks it against block headers from the public CometBFT RPC. The two public sentries take a state sync snapshot every 2,000 blocks, about every 3 hours, and keep the 2 most recent. Other mainnet peers also serve snapshots. In a test on 2026-11-09, a new node reached the latest block 30 seconds after it started and used 18 MB of disk.

1. Pick a trusted height and block hash from the public RPC. Choose a height a little behind the latest block and inside the trust period:

   ```bash
   RPC="https://rpc.mainnet.upside.net:443/tendermint"
   LATEST="$(curl -fsS "$RPC/block" | jq -er '.result.block.header.height')"
   TRUST_HEIGHT="$((LATEST - 2000))"
   TRUST_HASH="$(curl -fsS "$RPC/block?height=$TRUST_HEIGHT" | jq -er '.result.block_id.hash')"
   printf '%s %s\n' "$TRUST_HEIGHT" "$TRUST_HASH"
   ```

2. In `$NODE_HOME/config/config.toml`, set the `[statesync]` table, replacing the two placeholders with the printed values:

   ```toml
   [statesync]
   enable = true
   rpc_servers = "https://rpc.mainnet.upside.net:443/tendermint/,https://rpc.mainnet.upside.net:443/tendermint/"
   trust_height = <TRUST_HEIGHT>
   trust_hash = "<TRUST_HASH>"
   trust_period = "168h0m0s"
   ```

   Keep the trailing slash after `/tendermint/`. Without it, the public RPC answers the light client's requests with a redirect, the client loses the request body, and state sync stops at start with `failed to set up light client state provider ... 404 Not Found`. State sync requires two entries in `rpc_servers`. Listing the same server twice is accepted. The trust period of one week is shorter than mainnet's 21-day unbonding period.

3. Start the node as described in step 5. A successful sync logs `Discovered new snapshot`, `Snapshot accepted, restoring`, `Verified ABCI app appHash=...`, and `Snapshot restored`, in that order. The node then follows the chain normally.

4. After the first successful sync, set `enable = false` in `[statesync]`, so a restart doesn't try to sync again.

### Restore the signed mainnet archive

A sentry captures its data directory once a day at about 10:00 UTC. A separate verifier checks each capture against the public RPC, signs the manifest, and publishes it about 15 minutes later at [snapshots.mainnet.upside.net](https://snapshots.mainnet.upside.net/manifest.json). The site keeps the last 3 or 4 daily archives. An archive is about 6.1 GB and unpacks to about 9.7 GB. In a test on 2026-11-09, the whole path from download to the latest block took under 5 minutes on a cloud server.

Each archive contains only `config/genesis.json`, `data/application.db`, `data/blockstore.db`, `data/state.db`, `data/evidence.db`, and `data/upgrade-info.json` when present. It contains no binary, node key, validator key or signing state, address book, node configuration, transaction index, or consensus write-ahead log. Your node keeps the keys that `init` created in step 1. You also need `zstd`, `openssl`, and `ssh-keygen` from OpenSSH.

1. Download the manifest, its signature, and the newest archive:

   ```bash
   BASE="https://snapshots.mainnet.upside.net"
   curl -fsS -o manifest.json "$BASE/manifest.json"
   curl -fsS -o manifest.json.sig "$BASE/manifest.json.sig"
   URL="$(jq -er '.snapshots[0].archive.url' manifest.json)"
   curl -fL -C - --retry 5 -o chain.tar.zst "$URL"
   ```

   `manifest.json` lists the latest snapshots, newest first. Download the archive with a single request, as above. `-C -` resumes an interrupted download. The site limits each IP address to 600 archive requests in 5 minutes, so a download tool that splits a file into many small ranges can be blocked for a few minutes. If total downloads in a month pass a fixed limit, archive downloads pause until the next month. State sync keeps working.

2. Verify the archive. Stop if any check fails. The first two checks use the four files in [`docs/snapshots/`](../snapshots/) of this repository: [`allowed_signers`](../snapshots/allowed_signers), [`snapshot-key-statement.txt`](../snapshots/snapshot-key-statement.txt), [`snapshot-key-statement.txt.sig`](../snapshots/snapshot-key-statement.txt.sig), and [`snapshot-signing-pub.pem`](../snapshots/snapshot-signing-pub.pem). Set `KEYS` to that directory in your checkout:

   ```bash
   KEYS="/path/to/upside/docs/snapshots"
   ```

   The foundation signed the key statement, which names the snapshot signing key. This command checks the statement's signature against the SSH key in `allowed_signers`:

   ```bash
   ssh-keygen -Y verify -f "$KEYS/allowed_signers" -I snapshots@upside.net \
     -n upside-snapshots -s "$KEYS/snapshot-key-statement.txt.sig" \
     < "$KEYS/snapshot-key-statement.txt" \
     || { printf 'Stop: the key statement signature is not valid\n' >&2; exit 1; }
   ```

   It prints `Good "upside-snapshots" signature for snapshots@upside.net`. The SHA-256 of the public key in DER form must equal the value in the statement, `5a1d63be19b149c65d0bd75e94b4a9e4d82c11601109dd2571fe2ca6417d1c87`:

   ```bash
   KEY_SHA256="$(openssl pkey -pubin -in "$KEYS/snapshot-signing-pub.pem" -outform DER | sha256sum | awk '{print $1}')" || KEY_SHA256=""
   if [ "$KEY_SHA256" != "5a1d63be19b149c65d0bd75e94b4a9e4d82c11601109dd2571fe2ca6417d1c87" ]
   then
     printf 'Stop: the public key hash is %s, not the value in the statement\n' "${KEY_SHA256:-empty}" >&2
     exit 1
   fi
   echo "public key OK"
   ```

   The manifest must be signed by that key. This command prints `Verified OK`:

   ```bash
   openssl dgst -sha256 -verify "$KEYS/snapshot-signing-pub.pem" \
     -signature manifest.json.sig manifest.json \
     || { printf 'Stop: the manifest signature is not valid\n' >&2; exit 1; }
   ```

   The archive must match the manifest, and the manifest must match the chain. The app hash recorded for height H is the one in the header of block H+1, which describes the state after block H:

   ```bash
   S="$(jq -c '.snapshots[0] // empty' manifest.json)" || S=""
   H="$(jq -r '.height // empty' <<<"$S")" || H=""
   ARCHIVE_SHA256="$(jq -r '.archive.sha256 // empty' <<<"$S")" || ARCHIVE_SHA256=""
   BLOCK_HASH="$(jq -r '.block_hash // empty' <<<"$S")" || BLOCK_HASH=""
   APP_HASH="$(jq -r '.app_hash // empty' <<<"$S")" || APP_HASH=""
   case "$H" in
     ''|*[!0-9]*) printf 'Stop: the manifest has no valid snapshot height\n' >&2; exit 1 ;;
   esac
   if [ -z "$ARCHIVE_SHA256" ] || [ -z "$BLOCK_HASH" ] || [ -z "$APP_HASH" ]
   then
     printf 'Stop: the manifest is missing the archive checksum, block hash, or app hash\n' >&2
     exit 1
   fi

   printf '%s  %s\n' "$ARCHIVE_SHA256" chain.tar.zst | sha256sum --check - \
     || { printf 'Stop: chain.tar.zst does not match the manifest checksum\n' >&2; exit 1; }

   RPC="https://rpc.mainnet.upside.net:443/tendermint"
   CHAIN_BLOCK_HASH="$(curl -fsS "$RPC/block?height=$H" | jq -r '.result.block_id.hash // empty')" || CHAIN_BLOCK_HASH=""
   if [ -z "$CHAIN_BLOCK_HASH" ] || [ "$CHAIN_BLOCK_HASH" != "$BLOCK_HASH" ]
   then
     printf 'Stop: block %s has hash %s on the public RPC and %s in the manifest\n' "$H" "${CHAIN_BLOCK_HASH:-empty}" "$BLOCK_HASH" >&2
     exit 1
   fi
   echo "block hash OK"

   CHAIN_APP_HASH="$(curl -fsS "$RPC/block?height=$((H + 1))" | jq -r '.result.block.header.app_hash // empty')" || CHAIN_APP_HASH=""
   if [ -z "$CHAIN_APP_HASH" ] || [ "$CHAIN_APP_HASH" != "$APP_HASH" ]
   then
     printf 'Stop: block %s has app hash %s on the public RPC and %s in the manifest\n' "$((H + 1))" "${CHAIN_APP_HASH:-empty}" "$APP_HASH" >&2
     exit 1
   fi
   echo "app hash OK"

   VERIFIED=1
   ```

   Each check prints `Stop:` and a reason, and exits, if its value is empty or differs. The last line sets `VERIFIED=1` only after every check passes. On macOS, replace `sha256sum` with `shasum -a 256`. Both print the hash as the first field, which `awk` reads. A node restored from an altered archive can't follow the chain. At the first new block, its state gives a different app hash from the network's, and it stops with `wrong Block.Header.AppHash`. These checks catch that before you start.

3. Unpack the archive into the stopped home from step 1, and check the genesis file again. Run this in the same shell as step 2. The first command stops unless step 2 set `VERIFIED=1`, so the archive can't be unpacked without a completed verification:

   ```bash
   if [ "${VERIFIED:-0}" != 1 ]
   then
     printf 'Stop: verify the archive in step 2 before unpacking it\n' >&2
     exit 1
   fi
   tar -I zstd -xf chain.tar.zst -C "$NODE_HOME" \
     || { printf 'Stop: unpacking failed; inspect %s before retrying\n' "$NODE_HOME" >&2; exit 1; }
   printf '%s  %s\n' "$GENESIS_SHA256" "$NODE_HOME/config/genesis.json" | sha256sum --check - \
     || { printf 'Stop: the unpacked genesis file does not match GENESIS_SHA256\n' >&2; exit 1; }
   ```

   Unpacking takes about 2 minutes. Keep `enable = false` in `[statesync]`, and start the node as described in step 5. It catches up from the snapshot height to the latest block. In the 2026-11-09 test, an archive captured 5 hours earlier, about 3,300 blocks behind, caught up in 91 seconds.

## 5. Start and verify synchronization

Start the node with gRPC on loopback. This enables the transaction service used by automatic gas simulation through RPC. The HTTP API, EVM JSON-RPC, and profiling listener are disabled:

```bash
"$UPSIDE_BIN" start --home "$NODE_HOME" \
  --rpc.pprof_laddr "" \
  --minimum-gas-prices "$NODE_MIN_GAS_PRICES" \
  --api.enable=false --grpc.enable=true --grpc.address 127.0.0.1:9090 \
  --grpc-web.enable=false --json-rpc.enable=false
```

In another shell, you can query the local CometBFT RPC address configured in `config.toml`:

```bash
curl --fail --silent --show-error http://127.0.0.1:26657/status \
  | jq '.result | {chain_id: .node_info.network, sync: .sync_info}'
```

Use your configured port if it differs. Check the response:

1. Match the chain ID to the selected network.
2. Confirm that the block time is recent and height advances between checks.
3. Wait for `catching_up: false`.
4. Compare the height with an independent published endpoint to check that your node has reached the network's latest blocks.

For long-running operation, stop the foreground process cleanly and install a service with the same binary, home, and startup settings. `upsided` needs the `HOME` environment variable at start, and a systemd unit doesn't set it by default. Add `Environment=HOME=<the service user's home>` to the unit. Without it, the binary stops with `panic: $HOME is not defined`. The [operations guide](operations.md) describes the service and monitoring requirements. Never start a second process using the same node home.

You now have a synchronized full node. Validator registration and active-set checks are in [create a validator](../validators/create.md).
